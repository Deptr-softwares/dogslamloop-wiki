# Shared code

What every page loads before its own scripts: the reader's settings, paths and page addresses, the Supabase client, the escapers, the role ladder, the dialog engine, media helpers, accounts, and the site's lookups (character colours, aliases, accolades, icons). Readers, editors and staff all run it.

## Files

- `js/utility/site_utils.js`: Site Settings, paths and page addresses, the Supabase client and its local-only override, the escapers, the role ladder, the system alert, the dropdowns, the dialog engine (`openDialog`, `runDialog`), the confirm and prompt any page can use (`siteConfirm`, `sitePrompt`), and the mobile preview switch.
- `js/utility/site_data.js`: page data (`docs/page-data.md`). The delta engine is `js/utility/submission_delta.js`, which only the editor, the Overseer and History load.
- `js/utility/site_media.js`: media framing, the blocked-media guard, the shared tooltip and math.
- `js/utility/site_account.js`: signing in, the alert box, public profile lookups, badges and role badges, and the openers for the account boxes.
- `js/utility/account_boxes.js`: the reader's own profile, another reader's public profile and the inbox, loaded the first time one opens (`window.loadSiteFile`, in `site_utils.js`).
- `js/utility/site_lookups.js`: character colours (generated), aliases, accolades, the site's icons, character icon paths, frame colours, the version line and the character theme.

They load in that order on every page, right after the Supabase library (`tests/site-utils-parts.spec.js`).

## Data

- `localStorage`: `dsl_site_settings` (Site Settings), `dsl_supabase_override` (the local-only override), `dsl_badges_pending` (a badge won signed out).
- `user_roles`, `user_profiles`, `user_notifications`, `media_moderation`, and the RPCs `claim_badge`, `get_public_profiles` and `get_user_expert_pages`.
- `data/navigation.json`, `data/archived-pages.json`, `data/site_meta.json`.
- `site_pages.color`, copied into `site_lookups.js` between its generated-region markers by `scripts/fetch-content.js`.

## Watch for

- One escaper, `window.escapeHtml`; `page_router.js` keeps its own copy because it runs first. Test: `tests/one-escape-helper.spec.js`.
- `ROLE_RANK` mirrors `role_rank()` in SQL, and the SQL one is the boundary. Never test a role by name (CLAUDE.md, Roles). The role badges are the one place matched by name: an icon is an identity, not a bar.
- `SITE_BADGES` and `claim_badge()` in SQL list the same badges.
- Only `CHARACTER_COLORS` in `site_lookups.js` is generated, between two markers that must stay exactly as they are: `scripts/fetch-content.js` refuses to write without them, and the content gate reads that region.
- The local-only override works on localhost alone, with a key set by hand, and shows a banner on every page while it is on.
- The blocked-media guard is a rendering guard, not a security control: a flagged file stays at its public address until it is deleted.
- A box is a `<dialog class="site-dialog">` opened by `window.openDialog`, and whether it is open is `dialog.open`, never a `hidden` class. It sits in the top layer, so a popup opened from inside a box has to be inside it too, or it ends up underneath: the site tooltip moves into the open box that holds what is hovered (`site_media.js`, `tests/site-dialogs.spec.js`).
- Escape closes a box without pressing any of its buttons, so what a box does on closing (answering cancelled, disarming a picker, redrawing a list) runs on its `close` event, never only in its own button.
- The site's dropdown (`initializeMangaSelects`) dispatches only `change`. Its button is named by the select's `<label>`, a `<label>` written just before the select, or the select's `aria-label`; a select with none of them is a control with no name to a screen reader (`tests/axe.spec.js`, `tests/site-dropdown.spec.js`). The Block folder picker draws its own rows on the same parts and opens through `setDropdownOpen`, which keeps `aria-expanded` true to the screen.
- No page uses the browser's own alert, confirm or prompt: `npm run lint` refuses them (`no-alert`), and a page without the editor's box asks in `siteConfirm` or `sitePrompt`.

## Decisions

Newest first. One entry per decision.

- **2026-11-26, v1.3, #316.** The site's dropdown works by keyboard, like the browser's own (WAI-ARIA's select-only combobox): Tab reaches its button; Enter, Space or an arrow opens it; the arrows, Home, End and typed letters move; Enter or Space picks; Escape and Tab close it. Its look stays, and the Block folder picker takes the same keys. Until then no site dropdown could be reached by keyboard: its button was a div, and the select it stands for is hidden. Phones keep the site's dropdown rather than their own picker (the owner's pick, "Site dropdown"), so coloured options keep their colours. Claude's call: the dropdown stays the site's own rather than the browser's.
- **2026-11-25, v1.3, #315.** The editor's and Overseer's tool boxes are the same dialog, so no box on the site is a div with a z-index any more: QA submit (400, and 650 for its Long and Technical forms), Config (500), House Style and the Manual of Style (650), the notices and the move id box (400), Pull and the writing checks (500), Add a Gallery Item (400), Find & Replace, the Drafts Manager and the Merge Compiler (650), and the combo row and the Media Library (860). A click outside closes a box with nothing typed in it (the owner's rule from #314): a search is not typed work, and the combo row saves as it is typed, so both close; QA submit, Config, the move id box, the gallery item, Find & Replace, the library and the compiler stay open. Claude's calls: Find & Replace stays a box over the page rather than a side panel, which would be a new feature for the UI pass; the tour's spotlight stays outside the dialog, as in #314.
- **2026-11-25, v1.3, #314.** No box is the browser's own. Five were left: a Block delete and the link button on owner.html and tier-editor.html, which have no editor box (bug 9 of the review), deleting your own discussion post, the media library's clipboard message, and a sign-in that could not reach its provider. They ask in the site's boxes, and the lint's `no-alert` keeps new ones out.
- **2026-11-25, v1.3, #314.** Every box is one dialog: a `<dialog>` opened by `openDialog`, in the staff look, opening with fade and rise, at 400, 500, 650 or 860 wide (the owner's picks from mockups: "Staff box", "Fade and rise", "Four: 400, 500, 650, 860"). Escape closes any box, and a click outside closes one with nothing typed in it ("Esc always, click outside only if nothing typed"). The page behind does not scroll, focus goes back to what opened the box, and a box opened over another sits on top, which replaces the boxes' z-index values. Turned down: the reader box's look and three sizes (400, 560, 800), Claude's recommendations.
- **2026-11-24, silent release, #311.** No file stands in for the character-state helpers (`isBaseMode`, `getCharacterModes`, `BASE_MODE_ID`, `unwrapModeDelta`) or checks that they exist (the owner's pick). They were kept for a page whose new files met an hour-old cached copy of the shared one, which took the editor down on 2026-08-10. - **2026-11-23, silent release, #310.** The profile, a public profile and the inbox load the first time one opens (the owner's pick), from `account_boxes.js`; the inbox is no longer fetched at every page load, since the dock's unread dot has its own count. A file loaded later goes through `window.loadSiteFile`, which gives it the page's own `?v=` stamp, so it is never an older copy than the page.
- **2026-11-21, silent release, #298.** A page's kind comes from the site's own page list (`registeredPageType`), not from the submission, which is only the submitter's word (owner, 2026-11-21).
- **2026-11-21, silent release, #293.** One dialog engine (`runDialog`) runs every confirm, message and prompt box, and one question is open at a time, so a double click cannot run an action twice. One escaper (`window.escapeHtml`): 55 definitions were removed.
