# Character pages and Blocks

How a page's Blocks become HTML, and how a character page draws its tabs. Readers see it on every character and system page; editors see the same drawing in the editor's preview, and staff on the review screens.

## Files

- `js/pages/core/page_render.js`: the page renderer. Blocks to HTML on every page that shows them, a character page's tabs, a system page's tabs and sections, the video player and video modal, the clip queue, video stills and the missing-media box.
- `js/pages/core/skill_card.js`: the Skill Card, each move's box with its frame data.
- `js/pages/core/character_modes.js`: the mode toggle for a full character's ultimate states, and a base-only character's Ultimate tab.
- `js/utility/input_slots.js`: which input slot each move name belongs to, for colouring combo routes.
- `js/utility/character_tabs.js`: the tab list and the keyed sections the rest of the site derives from.
- `js/pages/core/format_tags.js`: the format tags, in `docs/format-tags.md`.

## Data

- `page_data.desc_data`: the page's text, as Blocks per part (`overview`, `strategy`, `extras`, `matchups`, the keyed tabs, `combos`, `techs`, `gallery`, `moveStrategies`), plus `profile` and `playstyle`. A system page's is `tabs`, each with `sections` of `blocks`. Written by approved submissions.
- `data/navigation.json`: the character list Previous and Next follow. Generated from `site_pages`.
- `data/video-stills.json` and `medias/stills/`: each video's first frame and size. Generated nightly by `scripts/fetch-video-stills.js`.
- `localStorage` `dsl-combo-notation`: the notation style a reader picked.

## Watch for

- Every value from page data goes through `window.escapeHtml`, in text and in attributes. A CSS value is allowlisted instead (`safeBlockAlign`, `safeBlockWidth`, `safeColor`). Tests: `tests/block-fuzz-escaping.spec.js`, `tests/render-escaping.spec.js`.
- The editor's preview calls these same functions on every keystroke. Anything a reader sets by clicking (an open accordion, a chosen tab) has to survive the repaint, through `captureNestedViewState`. Test: `tests/combo-card-sections.spec.js`, "the open tab survives the preview repaint".
- Every file a page loads shares one global scope, so a top-level name can be used once. Test: `tests/global-scope-collisions.spec.js`.
- The character and system boot paths in `page_boot.js` differ on purpose (CLAUDE.md).
- `loadPageDescriptions` only logs an error, and the page stays empty.
- Five specs read `page_render.js` as text: `block-styling-coverage`, `combo-card-sections`, `render-escaping`, `sectioned-box` and `theorybox`. Renaming a function or a class they look for fails them.

## Decisions

Newest first. One entry per decision.

- **2026-11-20, v1.2, #287.** Clips start downloading one screen ahead, not two. Cached egress stood at 155 of the plan's 250 GB 16 days into the month (2026-11-19), and a clip two screens down is often one the reader never reaches.
- **2026-11-19, v1.2, #283.** The Color Codes page's swatches are a Color Swatches Block, drawn from the site's own colours: a character's from `site_pages.color` (`CHARACTER_COLORS`), the frame and overlay colours from the legend `site_lookups.js` reads out of `ColorCoding.css`. No editor types them, so the page cannot fall behind them.
- **2026-11-19, v1.2, #283.** The Collaborators page is edited in the editor, one Collaborator Block per person: a Card (Main Contributors) or a Thanks line (Special Thanks). Cards side by side share one grid, lines one list. The home page's Credits list is built from the same Blocks (`scripts/fetch-content.js`), so the two cannot drift.
- **2026-11-18, v1.2, #280.** A Skill Card shows a move's accolades as badges under its name, picked in the editor from the list in `site_lookups.js`, each with its name and meaning on hover. No two of one opposite group (safe and punishable on block, and the rest) can be ticked on one move.
- **2026-11-17, v1.2, #279.** A video shows its first frame, at its real shape, until it plays, so the page does not jump. The owner: "For videos that takes time to load, there should be a thumbnail that stands in place for those videos with the exact dimension it has", and the first frame was their pick. A still is fetched only within three screens, so a page with 33 clips does not fetch 33 pictures for a reader who reads the top, and only a page showing one of our videos fetches the list.
- **2026-11-16, v1.2, #273.** A move can be marked No frame data (a passive, a dash variant). Its description takes the Frame Track's space, and nothing says frame data is missing. The stored tracks are kept, so unticking brings them back (owner).
- **2026-11-16, v1.2, #273.** Each Micro Variant (each timeline, however deep) can carry its own media, and the Skill Card's media box follows the one on show. A timeline without any shows the move's media (owner).
- **2026-11-12, v1.2, #270.** The Reverse Hitcancel overlay is retired (owner): no Frame Track used it, and an old revision that names it draws nothing.
- **2026-10-23, v1.1, #249.** Trivia lists every fact in the profile card, one a line. "Label | text" shows the label underlined, with the text on hover or on a tap. Turned down: one "2 facts" row whose facts opened on hover.
- **2026-10-23, v1.1, #249.** Character Navigation is two tiles, each the character's icon framed in their colour with their name (the owner's pick from mockups).
- **2026-10-20, v1.1, #238.** Quote, Trivia and Character Navigation sit in the profile card under the stats, the way a wiki infobox ends in its navigation rows, and the editor's preview draws them with the same function. Turned down: a first version across the page under the Overview, which "looks really awkward" (the owner). Previous and Next follow the Characters page's order, base-only characters last (owner, 2026-10-19).
- **2026-10-20, v1.1, #238.** A heading looks the same in every tab. Its coloured side bar is the Heading Block's own choice, in any tab (owner, 2026-10-19). Turned down: the bar Matchups, Counterplay and Starter Guide added by themselves.
- **2026-10-08, v1.0, #224.** Anchors are made from what the reader sees: format tags are taken out of a heading's text on the page and in the data alike (`stripStyleShortcodes`). Before, every link to a styled heading, and 49 search entries, pointed at an id nothing had.
- **2026-10-08, v1.0, #224.** A Combo Card's name is a heading, so it gets an anchor and a line in the contents. Practicality is free text (the owner: "You can enter anything"), and a column only when some row fills it.
- **2026-10-06, v1.0, #220.** YouTube embeds use the privacy-enhanced address (`youtube-nocookie.com`): no cookies until the reader presses play. The Privacy Policy says so.
- **2026-09-29, v0.20, #208.** An autoplaying clip has a small play button in its corner that opens the player with controls and sound, and the clip keeps looping. The owner: "On autoplaying video, give the option (as a small play button in the corner of that video) to open up a modal that play the video with controls on". One helper (`wikiClipHTML`) draws every clip, so the four places a clip shows cannot drift.
- **2026-09-29, v0.20, #208.** Clips load through a queue: within a screen of the reader, two at a time, the nearest first, and a loop plays only on screen. Measured on Puppet Master's Overview (2026-09-28): clips started only 300px ahead and shared the connection, a 0.31 MB clip waited 4.9 s behind a 4.24 MB one, and 11 of 26 were blank two seconds after scrolling into view. After (2026-09-29): no clip blank for over 2 s, and at most 7 requests in flight on a phone profile (9 before).
- **2026-09-28, v0.20, #206.** The tabs run Overview, M1s, Skills, Innate, Combos, Techs, Starter Guide, Matchups, Counterplay, Ultimate (base-only characters) and Gallery: the kit first, then how to use it (owner). Specials shows as Innate, and only the label changed: stored frame data, delta scopes, history and open submissions all name a tab by its id.
- **2026-09-28, v0.20, #206.** Media that fails to load shows "[ Missing Media ]", the box a skill card with no media already showed, so a reader can tell missing from slow. On 2026-09-28, 86 of the 466 files the wiki linked to did not exist, on 15 pages. Opt-in by class: portraits, roster icons and tier-list art keep their own fallbacks.
- **2026-09-28, v0.20, #205.** A combo can carry its route in more than one notation style, and the reader switches by clicking the route. The author types each style's label; a reader's choice applies to every combo and is remembered (owner, 2026-09-25). Spec: `.claude/archived-devlogs/V0.20-DEVLOG.md`, "notation styles on combo routes".
- **2026-09-24, v0.20, #203.** A repaint keeps the reader's open accordions and chosen tabs, matched by position, because a title changes while it is typed. One implementation serves both repaint paths: with it only in `populateTextSection`, the Combos preview snapped back to the first tab while the form edited section 2 (found by the owner, 2026-09-20).
- **2026-09-20, v0.19, #198.** A Combo Card can hold Multiple Sections, each tab a whole variant (route, damage, difficulty, clip, write-up), drawn with the Section Box's tabs. The tab label and the card heading are separate fields because the owner's reference has them differ ("In Corner 6H" over "Optimized 6H Counterhit Corner Starter"). A section with no route and no damage reads as prose, so a Preface tab needs no second Block type.
- **2026-09-20, v0.19, #198.** Seconds are a third way to give a phase's length, beside counted frames and an estimate, not in place of either (owner, 2026-08-24). Some phases are timed, not counted (a long animation, a cooldown, a state of about two seconds), and 120 in a frame box claims a precision nobody measured. JJS runs at 60fps server-side, so a second is exactly 60 frames. A timed phase draws solid, like an estimate, and its hover gives both units.
- **2026-09-20, v0.19, #198.** The Section Box: a title, an introduction and switchable tabs, each holding Blocks. It wears a Combo Card's frame only inside a Combos or Techs group, and asks `getDocumentSections` rather than naming those tabs.
- **2026-09-20, v0.19, #198.** A list can be boxed: "visual only, a sleek clean border around the list" (the owner's spec). Opt-in per list. Turned down: boxing every list, which would change hundreds of existing pages.
- **2026-09-16, v0.19, #193.** The full-text search index takes the Block keys that hold readable text (`TEXT_KEYS` in `character_tabs.js`), not every string: the rest is machinery, and an index of storage addresses is worse than none.
- **2026-09-09, v0.18, #182.** A system page's sections are in-page link targets too, walked in the order they render, so a repeated title is numbered the way the page numbers it.
- **2026-09-09, v0.18, #184.** The Gallery tab is a keyed section with one delta per item, keyed by name, so two contributors adding different clips never collide. Its scope is `charGalleryItem`, not the gallery page type's `gallery_item`.
- **2026-09-09, v0.18, #184.** The character Gallery tab draws `desc_data.gallery`. Its card is a deliberate copy of `gallery.js`'s: that file is the gallery page type and is not loaded on a character page, and sharing about thirty lines would add a script tag to every character page. The two may diverge (a gallery page is about a hundred searchable emotes, a character's a handful of clips), so it has no search box. A `modeScoped: false` tab like it belongs to the character and is not drawn again on a mode switch.
- **2026-08-20, v0.15, #120.** Techs is a second document tab: the same three parts as Combos under other names (Technical Overview, Tech Groups, Tech List). Every difference between the two is a string in `character_tabs.js`, and their fields and scopes are separate, so an edit to one can never touch the other. Techs is optional, off until the owner turns it on for a character (`page_data.tab_settings`). The flag is applied in one place, `getCharacterTabs`, so a tab switched off is gone from the editor and the Overseer too. Off is the default, and what a failed fetch gets.
- **2026-08-18, v0.15, #116.** Videos play in our own native player, not YouTube's: YouTube's controls cannot be restyled from outside its frame (the owner's call). Turned down: an external player API on the busiest pages, and a frame that promised more than it delivered. A video Block with controls off is a muted autoplaying loop standing in for a GIF.
- **2026-08-18, v0.15, #116.** A video in a table cell or a card is a button that opens the video modal. Turned down: a link to the file, which took the reader off the wiki to a bare video on a Supabase domain (owner, 2026-08-18).
- **2026-08-18, v0.15, #116.** A wiki-media address in a table cell shows as the media itself: an image sized to the row, a video as a button. Only addresses in our own `wiki-media` bucket, so a contributor cannot embed or hotlink from anywhere.
- **2026-08-18, v0.15, #116.** An image, video or YouTube Block with no address shows a placeholder (the site's icon, labelled Placeholder), so an author can see the Block is there. Turned down: a broken image box, or nothing at all.
- **2026-08-17, v0.15, #108.** The Combos tab is a document in three parts: Read First (a card of prose), the author's groups (headings, with the Combo Cards under them as the sections), and the Combo List. A group in a card made every Combo Card a card within a card (owner, 2026-08-16). The list is adapted from Dustloop's combo table in our own look: grouped by starter, the group names the author's, one sortable table per group. It is not a Block type: `desc_data.combos` is a keyed array like matchups, so submit, merge, diff and the editor's group nav come from the shared machinery.
- **2026-08-17, v0.15, #108.** The Combo List's columns: Setup and Controls show only when some row fills them, decided across the whole tab so its tables share a shape. Difficulty sorts by the owner's scale, not alphabetically. Ult Gain and Evasive Gain, the owner's two resources in place of the reference's Tension, Blood and Stamina, are bold lines above the notes, not columns.
- **2026-08-17, v0.15, #109.** In-page link targets are read from the data, not the page, because the editor draws only the tab being edited. Moves are targets (their names are in frame data), and a matchup's target is its heading, "vs. X".
- **2026-08-16, v0.15, #104, #106.** The character tab list is one module that every page, the editor and the Overseer derive their lists from; it was written out by hand at about 20 places in 13 files. Keyed sections (Matchups, Counterplay, Starter Guide and the parts of a document tab) are declared there too, with their delta scope stated rather than derived from the tab id. Starter Guide is Counterplay's shape without an importance (owner).
- **2026-08-16, v0.15, #105.** A Combo Block's route and damage sit on one row with the note underneath, full width, so the note reads as a condition on the whole combo. Steps are separated by `>`, as the community writes them. Turned down: the damage at the far right of the column with the note beside it.
- **2026-08-16, v0.15, #105.** Contributor Block content is escaped, and a CSS value (alignment, width) is allowlisted rather than escaped.
- **2026-08-11, v0.12, #44.** A phase's length can be an estimate, seven steps in the owner's own wording from Non-existent to RIP, for someone who knows how an endlag feels without counting frames. An estimated phase draws as a smooth block with no tick divisions, the owner's design: the ticks mean counted, and leaving them out also withholds a per-frame view that would mean nothing. The legend says so once, and the hover says "Estimated".
- **2026-08-10, v0.12, #43.** A full character's ultimate states are a toggle above the tabs, and the tabs draw again for the chosen state (Gallery stays). A base-only character's ultimate is one attack, so it gets an Ultimate tab after Counterplay; it shows even when empty, and on any page that has ultimate moves. Both are added at runtime, so a new mode shows once approved rather than at the next regeneration. The state is in `?mode=`, so a shared link opens on it.
- **2026-08-10, v0.12, #40.** Contributor credit is one footer per tab, sorted alphabetically, made by a pass over the finished tab rather than threaded through every caller: four code paths build sections, some of them asynchronously. Blog posts keep their own footer, since a post has one author.
