# The page shell

What every generated page is built from before its content arrives: the skeleton (both sidebars, the header, the tab strip), the boot sequence that fills it, the 404 rescue, the search box, and the gallery and tool page types. Readers see it on every character, system, gallery and tool page.

## Files

- `js/pages/core/page_router.js`: the skeleton a stub gets, written before the script that builds it.
- `js/pages/core/page_boot.js`: what each page kind runs once the skeleton is in.
- `js/pages/core/page_rescue.js`: on `404.html`, draws a page that exists in `site_pages` but has no stub yet.
- `js/utility/search.js`: the search box in the left sidebar.
- `js/pages/types/tool_page.js`: the tool page type, a host for a tool's own renderer.
- `js/pages/types/gallery.js`: the gallery page type, a flat searchable list of media.
- `js/pages/core/page_shell.js`: the sidebar and its dock, the phone bar, the Edit and History buttons, tabs, section anchors, the table of contents, page alerts and the footer. The hubs' roster and directories are in `js/dashboards/hub_roster.js` (`docs/home.md`).
- `scripts/page-scripts.js`: the scripts each kind of page loads, in order. The generator writes a generated page's tags from it, and `npm run generate` writes the marked block in each hand-written page.

## Data

- `window.PAGE_ROUTE`: `{ pageId, pageType, title }`, set by each stub in `<head>` (`scripts/generate-pages.js`).
- `site_pages`: what `page_rescue.js` asks about an address with no stub.
- `data/search-index.json`: every page name, section heading and move name, with its anchor. Generated by `scripts/fetch-search-index.js`.
- `page_data.desc_data`: a gallery's `items` and `intro`; a tool page's `tool`, `intro` and `notes`.

## Watch for

- `page_router.js` runs before `site_utils.js` and `site_lookups.js`, so it keeps its own escaper and writes the icon markup itself. Hand-authored pages never set `PAGE_ROUTE`. Test: `tests/page-skeleton-parity.spec.js`.
- `page_boot.js` stays the last script on a stub, so `site_lookups.js`'s character theme runs first. Its character and system branches differ on purpose (CLAUDE.md).
- Every tab button `page_router.js` draws must be bound by `page_boot.js`, optional ones included, or it ships unclickable.
- A rescued page is still an HTTP 404, so crawlers and Discord previews do not see it until the stub is generated.
- A page's scripts change in its list in `scripts/page-scripts.js`, then `npm run generate`, never in the page: `npm run validate` fails a block that does not match its list, and a script tag outside the block. Test: `tests/page-scripts.spec.js`.
- The page templates hold HTML comments of their own. They are template text, so they reach readers, and the comment trim left them alone.

## Decisions

Newest first. One entry per decision.

- **2026-11-23, silent release, #310.** The page builder is split by who uses it: the roster, the home page's category columns and the Systems directory are `js/dashboards/hub_roster.js`, which only the three hubs load, and the rest is `page_shell.js` (the owner's names). Every other page loads 6.6 KB gzipped less.
- **2026-11-23, silent release, #309.** Each kind of page has one script list, in `scripts/page-scripts.js`. The generator writes a generated page's tags from it, and each hand-written page has one marked block that `npm run generate` rewrites (the owner's pick). A file renamed or added changes one list, not 74 pages. Every page loads the scripts it loaded before, in the same order.
- **2026-11-19, v1.2, #284.** Hovering a roster card for about 0.25 s opens the character's banner with the start of their Overview. The owner's card: "When hovering above a character box icon in the roster selection section for about 0.25s, a banner pop up that have a custom wide stretch image (different from the portrait) with a cut-off Overview." The banner and the line come from `data/banners.json`, mirrored nightly, so a hover asks Supabase for nothing. A mouse or a keyboard only: a tap opens the page.
- **2026-11-17, v1.2, #275.** A phone gets a bar fixed to the bottom of the screen with search, the account, Site Settings and Ko-fi, on every page that starts the phone navigation (the owner's pick). Their card: "No quick way to start searching the wiki on mobile (need to press on the burger first in order to search)". Each button calls what its desktop twin calls.
- **2026-10-29, v1.2, #262.** History draws a past version of a character page with the live page's own steps (`bootCharacterContent`), rather than a copy of them that would drift.
- **2026-10-22, v1.1, #246.** A tool page lists its headings like a system page. With none, as on most tools, "On this page" is hidden rather than titling an empty list (owner, 2026-10-22).
- **2026-10-22, v1.1, #244.** The tab a reader is on is kept in the address (`?tab=`), so Back, a refresh and a shared link reopen it. The owner: "I can't click go back on my browser and conveniently go back to the last tab I clicked on". Replaced, never pushed, so Back leaves the page (the owner's pick).
- **2026-10-20, v1.1, #240.** Site Settings shares the account button's row in the dock: a row of its own pushed the account out of sight on a short screen (owner).
- **2026-10-20, v1.1, #238.** An in-page link shows on hover which section it goes to, and names the tab when the section is on another one. The owner (2026-10-19): "Hover over will tell which section it is heading to".
- **2026-10-08, v1.0, #227.** The roster has no tier filter: the owner had the tier field dropped, as it read "TBD" on every character.
- **2026-10-08, v1.0, #224.** A Combo Card's name, and each section's on a multi-section card, is an anchor (the owner: "so you can link sections to a combo card within a page"). A jump into a Section Box or a multi-section card switches it to the target's tab.
- **2026-10-07, v1.0, #221.** Ko-fi sits at the top of the right sidebar wherever a page has one; under the left sidebar's categories and the dock it was buried (owner). A page without a right sidebar keeps it on the left.
- **2026-09-28, v0.20, #205.** Arriving by a section link looks for the target, lands, then follows it while content above it grows, moving instantly. The owner's report: a search hit for Murmurate on Crow Charmer stopped at Circling; measured, the target was at 4,035px when the jump fired and at 6,679px 180 ms later. The reader's own scroll, key, click or touch ends the follow.
- **2026-09-10, v0.19, #192.** The search box finds page names, section headings and move names; body text has its own page, `search.html`. The owner: "structural for a short search, full text for a dedicated page". The index loads on first focus, not with the page: 83 KB of JSON (about 14 KB gzipped) to parse on every page view, for readers who never search.
- **2026-09-04, v0.18, #159.** A page expert sees the OVERSEER button, like a reviewer or a moderator. The dock's list and `admin-core.js`'s gate were changed together, as they always are.
- **2026-09-03, v0.17, #152.** The systems directory puts Guides first and System Pages last, the rest in the registry's order (owner). The dashboard columns carry no WIP tag. The owner: "kinda off and not fitting. The WIP tag being on the left sidebar navigation is good enough".
- **2026-08-25, v0.16, #134.** Hidden characters stay out of the roster unless "Show Hidden" lets them in. "Hide WIP" was removed: every character was WIP, so it emptied the roster, and WIP says whether a page is finished, which readers do not filter on.
- **2026-08-24, v0.16, #127.** A roster card shows the character's icon once it has loaded; a missing icon leaves the plain colour card. WIP is a corner marker beside the Early Access star, not part of the name, since the name is hidden until hover (owner).
- **2026-08-17, v0.15, #109.** Section anchors are stable ids from the heading's own text (`sec-...`), swept over every tab, so a link keeps pointing at its section after another is inserted above it, and works before its tab is opened. The old positional ids and a hand-typed `#Section Name` still resolve.
- **2026-08-14, v0.14, #87.** On a phone, the bar's left control opens the navigation (which has its own link home) and the right one the contents, now a drawer: the only mapping a thumb can guess (the owner's call). The Edit and History buttons live in that drawer, so their duplicate pair in the page body went.
- **2026-08-13, v0.14, #76.** The jump-to-discussion button sits beside the mode bar, not inside it: the bar hides itself for a character with fewer than two states.
- **2026-08-13, v0.14, #75.** The discussion thread sits below the tabs, not in one: a tab is a section of the article, and a conversation behind a button nobody clicks dies quietly.
- **2026-08-13, v0.14, #76.** A moderator (`can_moderate`) sees the OVERSEER button. It is a capability, never a second role: `user_roles` holds one row per user.
- **2026-08-12, v0.13, #52.** The Others and Tools columns on the Main Dashboard are sub-grouped by category, and those categories leave the "Guides & Such" box.
- **2026-08-11, v0.12, #44.** `404.html` draws a page that exists but has no stub yet, so a page works the moment it is created. The owner: "I have no idea why there is this regeneration thing here that is blocking my feedback loop." It stays a 404, with a "Not published yet" banner, so an unpublished page is not indexed. Archived pages keep their tombstone.
- **2026-08-10, v0.12, #41.** Gallery and tool pages are page types with the system page's shell. A gallery is one flat, searchable list, not tabs: categories decided up front for something people search are worse than none. Its right sidebar has no contents list but keeps the Edit button. A tool page hosts a tool that registers its own renderer; the launch link is the fallback, because the Skill Builder ID Reader is only a link and a tool not yet written should say so.
- **2026-08-09, v0.11, #36.** Every page has a skip-to-content link, added by `page_shell.js` so no page can lack it.
- **2026-08-08, v0.9, #30.** Every character and system page is a generated stub that sets `PAGE_ROUTE`, and the skeleton markup is held once, in `page_router.js`. The boot is a separate last script, and its character and system branches keep their different orders.
- **2026-08-07, v0.8, #28.** The sitewide footer is added by script on every page with `.site-layout`, rather than copied into each page.
