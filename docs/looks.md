# Looks: the reader stylesheets

How the reader pages look: the shared stylesheets every reader page loads, the two looks they carry, and the stylesheets of the Forum and the Tier List page. Readers see all of it; the editor and staff pages load some of these sheets with their own.

## Files

- Every sheet holds both looks. Its plain part, in the `site` layer, is the Classic look: what Classic draws and nothing more. At its end, its Dogslamloop part, in the `dogslamloop` layer and inside `html:not(.look-classic)`, adds only what Default draws differently.
- `style/Common.css` opens with the palette: the colours the sheets share, one variable each (`--black`, `--white`, the status hues `--red`, `--green`, `--yellow` and `--purple`, the greys `--grey-05` to `--grey-e5`, named by their value, and the white tints `--tint-2` to `--tint-5`). Its `:root` has the five faces a reader can pick (`--face-finger-paint`, `--face-wild-words`, `--face-serif`, `--face-sans`, `--face-mono`), each named once, and the three fonts, `--font-body`, `--font-title` and `--font-label`, which each look points at a face and a reader's font setting can point at another.
- `style/Common.css`, `style/Layout.css`, `style/Cards.css`, `style/Buttons.css`, `style/Badges.css`, `style/Alerts.css`, `style/Modals.css`, `style/Forms.css`: the shared look, loaded by every reader page.
- Split from `style/Layout.css`, each loaded by the pages that draw it, right after it: `style/Blocks.css` (`docs/character-page.md`), `style/dashboards.css` and `style/posts.css` (`docs/home.md`), `style/tierlist.css` (`docs/tier-lists.md`), `style/search-page.css` (`docs/records.md`) and `style/post-editor.css` (`docs/owner-tools.md`).
- `style/ColorCoding.css`: the character, frame-data, overlay and input-slot colours, as custom properties.
- `style/FrameData.css`: the Skill Card and the Frame Track (`docs/character-page.md`).
- `style/discussions.css`, `style/forum.css`: threads and the Forum (`docs/discussions.md`).
- `style/certified-tier-lists.css`: the Tier List page (`docs/tier-lists.md`).

## Watch for

- `.claude/rules/practice-css.md` holds the CSS traps: restate `[hidden]` for every class that sets `display`, check every page a shared class is on, read only defined variables, close every comment once.
- Every stylesheet tag carries the shared `?v=` stamp (`tests/asset-stamping.spec.js`).
- Which sheets a kind of page loads, and in what order, is its list in `scripts/page-scripts.js`. Of two rules that tie, the later sheet's wins, so moving a sheet in a list can change the page (`docs/page-shell.md`).
- Moving a rule between `Layout.css` and a sheet split from it moves it in the cascade. A few rules stay in `Layout.css` for that reason, each marked: it loses a tie to a later `Layout.css` rule, as it always has. A rule that ends in `*`, like the `.space-y-*` spacing, can tie with any rule on its children.
- Every stylesheet is inside a cascade layer, and the order of the layers is stated once, at the top of `Common.css`, the first sheet every page loads. A rule in a later layer wins over any rule in an earlier one, whatever their selectors, and an `!important` in an earlier layer wins over one in a later layer. A rule outside every layer, like KaTeX's sheet or a `<style>` a script adds, wins over every layered rule.
- Something both looks draw the same goes in the plain part; something Default draws its own way goes in the Dogslamloop part. `html.look-classic` switches every Dogslamloop part off at once, and a browser that cannot read CSS nesting shows the plain look.
- Classic is the base and Default only adds. A plain rule states what Classic draws, never a value whose only job is to undo Default. A Dogslamloop rule states Default's own value; it writes `revert` only where that value is the browser's own and differs by tag (a heading's bold, in Common.css).
- A font a look decides is read as `--font-title`, `--font-label` or `--font-body`, never written out, so a reader's font setting reaches it. A pick sits on `<html>`'s own style, over either look.
- A colour the palette names is read as its variable, never written out (`tests/colour-palette.spec.js`). A colour used rarely keeps its value.
- The character theme (`applyCharacterTheme`, `site_lookups.js`) writes its colours and title rules into the `dogslamloop` layer under the same wrapper, so Classic never shows them. A colour in `<html>`'s own style attribute would win over every layer.
- An inline style beats every rule in every layer, so a colour a look decides is never written inline (the Update Log's version headings were).
- The editor and staff pages follow the reader's look. `editor.css`, which they all load, draws the palette's greys as Classic's five colours in its plain part, and its Dogslamloop part sets Default's own greys back; the status hues and the tints keep theirs.
- A change to either look is checked with `npm run snapshot` (`scripts/style-snapshot.js`) against the commit before it, and a difference in its specimen markup counts until no page that draws the element could show it.
- Every box is the site's dialog (`dialog.site-dialog` in `Modals.css`, `docs/shared-code.md`), in the staff look in both looks: Classic has no rule for it.
- A strip of tabs inside a page is `.sub-tabs` and `.sub-tab` in `Buttons.css`, its picked tab `.is-active`, and a strip sets its own colour with `--sub-tab-accent`. The page tabs (`.btn-manga-slanted`) and the mode chips are not part of it. A button in a strip that is not a tab is `.sub-tabs-action`.
- `.tier-portrait` is shared between the Tier List page and the tier editor; its size on the page is raised in `certified-tier-lists.css` only.
