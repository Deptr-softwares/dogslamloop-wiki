## Scope changes to the roadmap (owner, 2026-08-15)

- **Side-by-side character comparison — REMOVED.** Cut, not deferred; it should
  not reappear in a later version's scope.
- **Tier-list edit-in-place — REPLACED** by **Create Tier List**: a tool page
  under the Tools column's Community category. Drag-and-drop characters into
  tiers, tier names and colours customisable, one button to download the result
  as a PNG. No edit button and no History — it is a tool, not a page.
- **Skill Builder ID Reader — CONFIGURATION ONLY, no code.** The page exists
  already. Restricting it to the owner is `site_pages.edit_role = 'elevated'`
  plus a `page_permissions` row with `required_role = 'admin'`. Both values are
  already in the schema and already enforced server-side.
- **Multi-tab submission — MOVED to the bug list.** It is built; it drops data.

### The rule behind the ID Reader decision

**An editable `tool` page wraps an EXTERNAL tool** — the page is description,
link and context, so it is content, and content gets edited.
**A non-editable `tool` page has its logic IN the page** — Free Submit Tier
List, Create Tier List. Nothing to submit, so no edit button and no History.

## New features

1. **Paste a Supabase storage link into a table slot** and have it render the
   image or video there, sized down appropriately. `wiki-media` only.
2. **A real video player UI** for the video and youtube blocks — stylised,
   sharp, themed off the character accent so it changes per page.
3. **A Gallery tab on every character page** (distinct from the `gallery` page
   type used by Emotes). Reached by "edit this tab" like any other tab. Simple
   upload UI, no block-edit footer. Each card carries a title and a description
   *under* the media; the media field takes a Media Library link, so the file
   is uploaded there first.
4. **A placeholder for empty image and video blocks** — `DogslamloopIcon.webp`
   from `medias/images/` with "Placeholder" in Finger-Paint above it. Today a
   linkless block collapses its height and renders as an empty box reading
   "I am broken".
5. **Find and replace in the editor**, single and mass. Renaming "Ryu" to
   "True Cannon" currently means hunting through dozens of blocks by eye.
6. **Block folders in the editor.** Group blocks so a long page can be
   navigated instead of scrolled. Editor-facing only — no visitor sees it.
7. **Better character icons** in the roster selection on the Main and Character
   dashboards. Assets are already in `medias/images/`. **The owner has a
   concept image and a specific idea — ask before designing anything.**
8. **Insert sections in place, and reorder them.** Add buttons belong under
   each section rather than only at the end, and a section should move left and
   right. Today a new Skill 1 variant can only be appended, so placing it next
   to Skill 1 means re-editing every skill after it.
9. **Box-in a list** — visual only, a sleek clean border around the list.
10. **Hyperlink to a section or tab within a character page.** Mentioning "The
    Triple Drill Tech" in a Skill overview should link to the Tech section of
    the Overview tab. The ToC already resolves these targets.
11. **An extensive user profile system.** Today an account can change exactly
    one thing: display name. Wanted: change password (for non-provider
    accounts), a description/portfolio, a user flair shown beside the display
    name in discussions, a display of their standing (normal user, trusted
    editor, reviewer, moderator…), and a way to make the profile private.
    Clicking a username in a discussion opens their profile in a modal.
12. **A Game Version field on `tier-editor.html`** so a tier list records which
    version of the game it describes.
13. **An uploader credit for every item in the Media Library** — possibly a
    `media_uploader` table carrying the media link and the upload date.

Carried from the original v0.15 line and still open: **site-wide search**,

Search stays last deliberately — it is a discovery tool for content that does

## Three findings that change the shape of this list

Recorded before building, because each one moves an item.

**Bugs 3, 5 and 6 are probably one bug.** All three are the editor losing which
tab *and which character state* you were on. `window.currentEditorTabId` is a
single global with no state dimension — `js/editor-tabs.js` and
`js/editor-core.js` read it in eleven places — and the v0.13 plan already
recorded the related symptom that a contributor editing two states "leaves the
reviewer's preview opening on only one of them". Investigate the state axis
first and re-test all three before treating them as separate work.

**Fine-tuning 1 is mostly built already.** `data/page-previews.json` is exactly
the map that item asks for — `page_id` → portrait URL, generated from
`page_data.desc_data.profile.image` and refreshed by the nightly regeneration
job. It is currently only consumed for social preview images in the generated
stubs. The tier list pages need to read it rather than query Supabase, which is
wiring rather than a feature. **One consequence to accept:** portraits refresh
nightly, not instantly — and since regeneration now targets `next-update`, a
new portrait reaches the live site at the next release rather than the next day.

**Feature 2's colour token is `--accent-blue`, not `--color-blue`.**
`js/site_meta.js:159` sets `--accent-blue` to the character's colour, and there
is no `--color-blue` anywhere in the codebase. The per-character theming the
item wants already works; only the name in the list is off.

## Answered by the owner, 2026-08-16

**Create Tier List delivers to the clipboard, not a download.**

That does **not** remove the blocker, and the item should not be scoped as if
it does. `navigator.clipboard.write()` needs a `Blob`, the `Blob` comes from
`canvas.toBlob()`, and a canvas tainted by a cross-origin portrait throws
`SecurityError` at exactly that call. The CORS question is unchanged: every
portrait needs `crossOrigin="anonymous"` *and* the right
`Access-Control-Allow-Origin` from Supabase Storage. **Spike that before
scoping the rest.**

Clipboard is still the better UX, but it needs a download fallback — Firefox
and Safari have lagged on image writes through `ClipboardItem`, and this site's
own bug reports come from Firefox and Edge users.

**User flair: 30 characters, emoji allowed, no special characters, no slurs or
political/sensitive content.** Three things that follow:

- Allow-list the character set (letters, digits, spaces, `\p{Extended_Pictographic}`)
  rather than block-listing punctuation. "No special characters, emoji fine" is
  not expressible as a blocklist.
- **Count grapheme clusters, not `.length`.** One ZWJ emoji is up to 11 UTF-16
  units, so a naive 30-character check rejects a single emoji. `Intl.Segmenter`.
- Word filtering must be **server-side** — a client list is bypassable by
  calling REST directly — and no wordlist is complete, so flair must also be
  reportable through the existing moderation queue. The list is a speed bump;
  the queue is the actual control.

**A private profile is visible to the owner and to holders of a new
`can_view_private_profile` capability**, which is deliberately *not*
`can_moderate`. This needs no new mechanism: it is another boolean on
`user_roles` beside `bypass_cooldown`, `can_moderate` and `can_delete_media`,
following the v0.13 pattern exactly. RLS reads: not private, OR it is your own
row, OR `get_my_role()` is `'admin'`, OR the caller holds the capability.

**Usernames are being added, and `media_uploader` keys on `user_id`.** The
owner's reasoning — a raw id is a poor thing to display — resolves into the
standard split: a unique `username` for display and addressing, a free-form
`display_name` that can change, and `user_id` as the only thing stored on other
tables. Uploader credit then resolves at read time and never goes stale.

**One migration cost to plan for:** every existing account needs a username
backfilled, with a collision strategy. That is the part of the profile system
most likely to be underestimated.

## Carried in from v0.14

Not deferred features — these are known, measured and unfinished.

- [ ] **~17 `waitForTimeout` calls** across fifteen spec files. v0.14 took 42 to
      21; four of the survivors are deliberate (they assert that nothing
      happens, and polling can only wait for something to appear). The rest are
      the same three shapes and the work is mechanical
- [ ] **Suite worker scaling.** 4x workers buys 1.44x and 8 is slower than 4.
      Measured across v0.13 and v0.14: navigation dominates
      (`networkidle` ≈1474ms/nav against `domcontentloaded` ≈301ms), and the
      single-process Python test server degrades over a long run — it produced
      `ERR_NETWORK_IO_SUSPENDED` twice during the v0.14 release
- [ ] **Stylesheet order differs by page type.** Generated character stubs load
      `Layout.css` last; system stubs load it second. Any equal-specificity
      conflict between two shared stylesheets therefore resolves differently
      depending on the page — found when the same sidebar button measured 45px
      tall on one page type and 34px on another. That instance is fixed at
      source; the hazard remains and nothing detects the next one
- [ ] **Flagged-media deletion vs the garbage collector.** If flagging deletes
      the object, the collector's reference scan and the moderation table can
      disagree about a file that no longer exists. Decide which is
      authoritative before both are automated
- [ ] **Contributor leaderboard** (v0.14 item 4, never started)
- [ ] **The 40 skipped probes.** `scripts/probe-release.js` needs `USER_JWT`,
      `ADMIN_JWT` and `--include-writes` against a preview branch. Since
      `supabase/seed.sql` landed, any preview branch has the accounts to do it.
      **The admin case is the one still unproven.**

## The release lesson v0.14 ended on

**`Supabase Preview` was not a required check.** It caught one of the two
migration failures and reported it in red on the release commit, which merged
anyway. Five of eight migrations did not apply and three features were inert in
production until a hotfix.

It is required on both branches as of 2026-08-15. That alone would not have
been enough — neither failure was visible on its own item PR — so
`supabase/migrations.lock.json` and a third check in
`tests/migration-columns.spec.js` cover the two ways a green preview still
lies. Both are recorded in the `supabase-migration` skill.
