## Constraints on F5, established 2026-08-24

- **`expert` cannot be a role.** `user_roles` has `UNIQUE(user_id)` and a `CHECK`
  allowing only `admin | reviewer | trusted_editor | viewer`. It has to be a
  separate column plus a new `can_review_page()` function.
- **"Default to the authenticated role"** is not a valid value in that CHECK.
  Needs resolving at design time.
- **Experts get a visible badge** (owner, 2026-08-24) — not only a queue
  permission.

`is_expert_of` holds a list of `page_id`s: a Crow Charmer expert has
`[crow_charmer]`, and a Register expert too has `[register, crow_charmer]`. An
expert can open, chat in and review tickets **only** for their own characters —
otherwise the same powers as a reviewer.

## What v0.16 leaves for it

**`role_rank()` already exists** (`supabase/migrations/20260825000001_role_rank.sql`,
plus `window.roleRank` / `window.roleMeets` in `js/site_utils.js`). It was built
for bug 6 — a reviewer never receiving the Trusted Editor perks — and it is the
one place that states how the roles order.

That matters here because **`can_review_page()` is the same shape of problem
one dimension further out**: not "is this person senior enough" but "is this
person senior enough *for this page*". Whatever it becomes should extend the
ladder rather than start a fourth independent list of role names — the reason
bug 6 existed at all is that every perk tested a literal.

**The `viewer` role is in the CHECK; `contributor` is not** — it was retired in
`20260808000006_role_cleanup.sql`. The inventory above said otherwise and has
been corrected here.

## Raised but unscheduled

**Pre-release character pages.** The devs may want a character page created
before the character ships. v0.16's `is_hidden` is **not** the right mechanism
for it: this repository is public, so a page's name, URL and generated stub are
committed regardless of any flag, and `is_hidden` only filters the roster
listing. Real pre-release secrecy needs the page not to exist in the repo at
all, which is a different feature. Full note at the bottom of
`devlogs/V0.16-DEVLOG.md`.

**The cache-stamp gap.** Only 3 of the 11 scripts a character page loads carry a
`?v=` stamp, so a release that changes an unstamped renderer can serve a fresh
skeleton against a stale script — reproduced 2026-08-20. The fix's scope is
undecided and it should ride along with other work rather than restamp 62 pages
on its own. v0.16 restamped twice as a side effect of touching `site_utils.js`,
which is one of the three that *is* stamped.
